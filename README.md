# BlameNet —— Windows 网络故障定位工具

严格按步骤、不跳过、只读诊断、不重装系统的 Windows 网络故障分层诊断工具。
一次性执行 31 个检查模块，输出完整证据链，并生成同源一致的多形态报告。

- 运行环境：Windows 10 / 11（依赖 PowerShell 与 Windows 原生命令行工具）
- 构建环境：Oracle OpenJDK **22.0.1** + Apache Maven **3.9.9**
- 运行期依赖：全部打包进单个可执行 jar（fat jar），除 Java 运行时外无需安装任何其他依赖；exe 安装包（jpackage）则自带精简运行时，无需预装 Java

---

## 1. 设计原则

| 原则 | 落地方式 |
| --- | --- |
| 只读优先 | 不执行 `ipconfig /release`、`/renew`、`/flushdns`、`netsh reset`、`sfc` 修复、`DISM` 修复等任何变更类命令，只输出建议 |
| 严格按步骤 | 31 个模块顺序执行，每个模块内的每个小步骤都会推进进度条，不跳过任何一步 |
| 外部验证不跳过 | 物理替换测试、干净启动、PE/Linux Live 对比、重装建议等无法在本机自动完成的项目，生成「外部验证清单」并标记为 手动 |
| 证据链完整 | 每个结论都附带真实执行过的命令、原始输出、记录时间、退出码与执行耗时 |
| 单一数据源 | JSON 是唯一主数据源；HTML / PDF / MD / TXT / XLSX / README.txt / manifest.json 全部由该 JSON 反序列化后生成，导出层不可能二次采集数据 |
| 展示层中文化 | 界面与报告把状态映射为中文（通过 / 警告 / 失败 / 手动 / 信息 / 已完成 / 严重 / 高 / 中 / 低）；源数据层的字段名、状态源值、原始命令与输出保持原样 |

唯一的系统级主动行为是「以管理员身份重新运行」，且必须由用户在界面上显式确认后触发。

## 2. 构建

```bash
# 依赖国内网络环境时，请先配置镜像（仓库中不包含任何镜像凭据）
# 本项目在本机使用阿里云 central 镜像完成依赖解析

cd BlameNet
mvn clean package
```

产物：

| 产物 | 说明 |
| --- | --- |
| `target/BlameNet.jar` | fat jar（含 Jackson / PDFBox / POI 等全部依赖），可直接 `java -jar` 运行 |
| `target/BlameNet-<version>.zip` | 发行包：jar + `BlameNet.bat` / `BlameNet-CLI.bat` + README.txt + LICENSE.txt |

## 3. 运行

```bash
# 图形界面（默认；无图形环境自动降级为命令行）
java -jar BlameNet.jar

# 命令行界面
java -jar BlameNet.jar --cli

# 快速档：缩减 ping 次数并跳过 sfc / DISM 深度扫描（调试用）
java -jar BlameNet.jar --cli --quick

# 只运行部分模块
java -jar BlameNet.jar --cli --modules 01,06,12

# 指定结果目录
java -jar BlameNet.jar --cli --output "D:\BlameNetResults"

# 不采集数据，仅从已有 JSON 主数据源重建全部报表
java -jar BlameNet.jar --report ".\results\BlameNet-2026-10-04-18-14-17.json"

# 完整档（默认，含 sfc / DISM 只读检查与 100 次网关 ping）
java -jar BlameNet.jar --cli
```

完整参数说明见 `java -jar BlameNet.jar --help`。

## 4. 界面

- **图形界面**：中部为「模块结果 / 模块详情 / 外部验证清单 / 运行日志」四个页签；窗口**最下方固定为进度条区块**，自上而下依次是「当前测试内容 → 实时进度条 → 状态与耗时」。支持外部验证项回填，并可一键重新生成全套报告。
- **命令行界面**：同样在终端底部原地刷新两行，上一行显示当前测试内容，下一行是进度条与步数/耗时/预计剩余；输出重定向到文件时自动退化为单行回车刷新，绝不写入光标控制序列。

进度总长度在预检阶段一次性确定（预检 4 步 + 31 个模块各自步骤 + 报告阶段 10 步），每个小步骤完成后必定前进，绝不回退。

| 01 | 检查网络适配器是否被系统识别 | 硬件/驱动层 | 4 |
| 02 | 检查设备管理器中的网卡状态 | 硬件/驱动层 | 4 |
| 03 | 检查 Wi-Fi 接口详情 | 硬件/驱动层 | 4 |
| 04 | 检查网卡硬件丢弃计数器 | 硬件/驱动层 | 5 |
| 05 | 物理连接替换测试 | 硬件/驱动层 | 3 |
| 06 | 查看完整 IP 配置 | IP/路由层 | 5 |
| 07 | 检查 DHCP 租约状态 | IP/路由层 | 4 |
| 08 | 检查 IP 地址冲突 | IP/路由层 | 4 |
| 09 | 检查路由表 | IP/路由层 | 4 |
| 10 | 测试本地 TCP/IP 协议栈 | 链路层 | 3 |
| 11 | 测试本机 IP 地址 | 链路层 | 4 |
| 12 | 测试到默认网关的连通性 | 链路层 | 4 |
| 13 | 检查 TCP/IP 连接统计 | 链路层 | 4 |
| 14 | 测试 DNS 解析 | DNS/传输层 | 4 |
| 15 | 清除 DNS 缓存并重试（只读检查缓存） | DNS/传输层 | 4 |
| 16 | 检查 DNS 客户端服务 | DNS/传输层 | 3 |
| 17 | 测试远程 TCP 端口可达性 | DNS/传输层 | 3 |
| 18 | 检查本机防火墙规则 | 安全/代理层 | 4 |
| 19 | 检查代理设置 | 安全/代理层 | 5 |
| 20 | 检查 hosts 文件 | 安全/代理层 | 3 |
| 21 | 检查网卡驱动版本与状态 | 驱动/系统服务层 | 4 |
| 22 | 取消网卡省电设置（只读检查） | 驱动/系统服务层 | 4 |

| 24 | 检查关键网络服务 | 驱动/系统服务层 | 3 |

| 28 | 检查 MTU 与分片问题 | 深度数据包层 | 8 |

故障分层归因规则（01-04 硬件/驱动层 → 06-09 IP/路由层 → 10-12 链路层 → 14-17 DNS/传输层 → 18-20 安全/代理层 → 21-25 驱动/系统服务层 → 26-28 深度数据包层 → 29-31 外部验证项）由 `RuleEngine` 依据真实模块状态计算，并据此给出风险等级（严重/高/中/低）。

## 6. 输出

结果只写入程序安装目录下的 `results/`（可用 `--output` 覆盖），文件名形如 `BlameNet-yyyy-MM-dd-HH-mm-ss`：

```text
results/
├── BlameNet-2026-10-04-18-14-17.json            ← 唯一主数据源
├── BlameNet-2026-10-04-18-14-17.html            ← 网页报告（推荐优先查看）
├── BlameNet-2026-10-04-18-14-17.pdf             ← 打印 / 归档
├── BlameNet-2026-10-04-18-14-17.md              ← Markdown 报告
├── BlameNet-2026-10-04-18-14-17.txt             ← 纯文本报告
├── BlameNet-2026-10-04-18-14-17.xlsx            ← Excel 报告（7 个工作表）
├── README.txt                                   ← 报告包说明
├── manifest.json                                ← 包清单（真实 SHA-256）
└── BlameNet-2026-10-04-18-14-17-bundle.zip      ← 以上全部文件的打包
```

JSON 顶层结构：`TestMeta` / `TestEnvironment` / `Summary` / `ModuleResults` / `ManualValidationList`。
`manifest.json` 中每个文件的 `sha256` 均由本机运行时真实计算，可用 `Get-FileHash` 或 `sha256sum` 复核。
若某一形态导出失败（例如系统缺少可用中文字体导致 PDF 无法生成），失败原因会如实写入 `manifest.json` 的 `failedExports`，不会静默隐藏。

## 7. 源码结构

```text
src/main/java/com/blamenet/
├── Launcher.java              入口：参数解析、单实例锁、界面选择
├── collect/                   只读采集层（PowerShell / CMD / 套接字探测、权限、命令外壳）
├── parse/                     输出解析层（ipconfig、netsh、ping、powercfg、Test-NetConnection 等）
├── model/                     报告数据模型（Report / TestMeta / Summary / ModuleResult / Evidence ...）
├── core/                      诊断内核（调度引擎、进度跟踪、规则引擎、模块基类与上下文）
├── modules/                   31 个检查模块 + 共享网络事实（NetFacts）
├── report/                    报告导出层（JsonStore、6 种导出器、manifest、ZIP、流水线）
├── ui/                        图形界面与命令行界面
└── util/                      时间、哈希、文本、JSON、路径、构建信息工具
```
